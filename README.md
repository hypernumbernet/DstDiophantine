# DstDiophantine

Lean 4 formalization of **Double Spacetime Theory** (DST), together with an
amplification programme — and an open **proof challenge** — for classical
Diophantine conjectures.

The machine-checked core is an algebraic bound and a shared no-go calculus.
Unconditional Fermat, Beal, abc, the Riemann Hypothesis, Goldbach, Polignac,
and Collatz are **not** claimed. Open work is named residual / `*Bridge`
propositions and six explicit `axiom`s; there are no `sorry` holes. Where a
paper draft disagrees with Lean, **Lean is authoritative**.

Entry point for the Diophantine path: [`DstDiophantine/Basic.lean`](DstDiophantine/Basic.lean)
(`import DstDiophantine.Basic`). Gravity, D4L, and CGA are parallel tracks and
are **not** re-exported from `Basic`.

## Double Spacetime Theory

DST rejects a single shared spacetime continuum. Each massive particle carries
its own pair of compact Minkowski structures inside the 16-real-dimensional
biquaternion algebra $\mathbb{H} \otimes_{\mathbb{R}} \mathbb{H} \cong \mathrm{Cl}(3,1)$:

- **usual** spacetime with basis $(j, kI, kJ, kK)$
- **dual** spacetime with basis $(k, jI, jJ, jK)$

The dual map $X \mapsto Xi$ reverses the arrow of time while preserving the
Minkowski norm. Lorentz transformations are generated by commuting rotors on
each sector. Gravity and inertia are read as **torsional mismatch** between
those rotors,

$$
\Omega = R_{\mathrm{usual}}^{\dagger}\, R_{\mathrm{dual}},
\qquad
J = \tfrac12\sum_{a=1}^{3}(\alpha_a^2 - \beta_a^2),
$$

not as curvature of a background manifold. Algebraic $J$ is **not** identified
with the Weitzenböck teleparallel scalar $T$.

The additive structure is then lifted into projective geometric algebra
$G(3,1,1)$ (null translators, ten bivector generators, motors $M = RT$).
Physics: [`papers/double-spacetime-theory.tex`](papers/double-spacetime-theory.tex).
PGA lift: [`papers/dst-pga.tex`](papers/dst-pga.tex).

## Algebraic core (proved)

- Clifford / PGA generators, motors, and the torsional scalars $J$ and
  $J_{\mathrm{norm}}$
- the admissible bound $|J_{\mathrm{norm}}| \le 1$ (equivalently
  $|J| \le 3\pi^2/8$)
- a faithful embedding of integers via rotors and null translators
- problem-independent amplification no-go theorems on the discrete torus

Shared no-go lives in [`Framework/Amplification.lean`](DstDiophantine/Framework/Amplification.lean).
The algebra barrel is [`DstDiophantine/Algebra.lean`](DstDiophantine/Algebra.lean).

## Diophantine programme

Integers embed into PGA motors. A power-sum equation such as
$a^p + b^p = c^p$ or $A^x + B^y = C^z$ becomes
`powerSumMotor = 1`. Dual-spacetime rapidities are discretized to a finite
torus $(\mathbb{Z}/N\mathbb{Z})^6$, so each problem is a search over an
**admissible** lattice subject to $|J_{\mathrm{norm}}| \le 1$.

Developed in [`DstDiophantine/Framework/`](DstDiophantine/Framework/) and
[`papers/dst-diophantine.tex`](papers/dst-diophantine.tex):

| Layer | Content | Status |
| --- | --- | --- |
| 1. Faithful encoding | Additive relations as null-translator motors | Proved |
| 2. Amplification no-go | A seed that amplifies past the admissible bound cannot exist (problem-independent) | Proved |
| 3. Bridge / residual | A classical solution would produce such a witness, or a named leaf after a closed case split | **Open** |

The challenge is layer 3: close a live residual, prove a live `*Bridge`, or
replace an `axiom` with an internal proof. Diagnostic bridges
(`FermatAdmissibleBridge`, `FermatModularBridge`, `BealModularBridge`,
`AbcAdmissibleBridge`, …) are **not** the live route.

## Build

Requires [elan](https://github.com/leanprover/elan) and the toolchain pinned in
[`lean-toolchain`](lean-toolchain) (`leanprover/lean4:v4.34.0-rc1`). mathlib is
the matching revision in [`lakefile.toml`](lakefile.toml).

```bash
lake build
```

CI runs the same build via [lean-action](https://github.com/leanprover/lean-action)
and generates docs with [docgen-action](https://github.com/leanprover-community/docgen-action)
on every push and pull request
([`.github/workflows/lean_action_ci.yml`](.github/workflows/lean_action_ci.yml)).
